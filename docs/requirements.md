# 「優しさの交換サイト」要件定義書（UI/UX統合版）

## 1. サービスコンセプトと目的

### コンセプト
不特定多数のユーザーが匿名で心のモヤモヤを吐き出し、AIではなく生の人間が優しい言葉や励ましを投げかけることで、優しさを循環させるプラットフォームです。

### 目的
営利を目的とせず、**「人に優しくすることで、自分自身も癒される」**という心理的効果を提供し、自己肯定感を高める場所を目指します。

### 基本方針
費用をかけず、無料枠の範囲内で開発・運用を完結させます。

## 2. UI/UXデザイン要件（※Gravityを参考にした指針）

「肯定の場」を視覚的に表現し、ユーザーが安心して利用できる環境を整えます。

### ビジュアルスタイル
- Gravityをベンチマークとし、角の取れた丸みのあるパーツや、目に優しいパステルカラー、低彩度の配色を採用します。

### 心理的障壁の除去
- 投稿画面は「独り言」をそっと置くようなシンプルな構成とし、入力のハードルを最小限に抑えます。

### ポジティブ・インタラクション
- 「ありがとう」「心が温まった」といった具体的な言葉を添えたアイコンを配置し、迷わず優しさを送れる設計にします。

### 比喩の反映
- 「公共の庭」という比喩に基づき、植物や自然を感じさせる温かみのある装飾を随所に施します。

## 3. ユーザー機能要件（ユーザーができること）

### 基本機能
- **心のモヤモヤ投稿**: 匿名またはIDベースで、悩みや独り言を投稿できる機能。
- **優しさの返信**: 実在のユーザーによる、生の人間としての励ましや返信機能。
- **ポジティブ・リアクション**: 肯定的な感情に特化したボタンによる反応機能。
- **投稿閲覧**: 新着順、ランダム、リアクションが多い順など、他者の投稿に触れやすい表示機能。
- **貢献度の可視化**: 「感謝の履歴」やランキング形式で優しさの貢献度を表示する機能。

### 追加機能
- SNS認証を用いた簡単ログイン
- 反応があった際の通知機能
- 匿名性を守るためのニックネーム設定

## 4. 安全・管理要件（コミュニティを守る仕組み）

### コンテンツ管理
- **有害コンテンツのフィルタリング**: 自作のNGワードリストによるキーワードフィルタリングの実装。
- **違反者への対応**: 利用規約違反者に対するアカウントロックや一時停止の管理ロジック。
- **匿名性の確保**: 安心して本音を吐き出せるプライバシー配慮設計。

### 通報機能
- ユーザーが不適切な投稿を運営に報告できる仕組み。

## 5. 技術・非機能要件（システムの品質や制約）

### 技術スタック
- **フロントエンド**: Next.js (React) による高速動作。
- **ホスティング**: Vercel による運用費の無料化。
- **バックエンド/DB**: Firebase (Firestore) によるリアルタイム同期と無料枠活用。

### 運用コストの最小化
- **VercelやFirebaseの無料枠（Spark Plan等）**を最大限活用した0円運用。

### データのクリーンアップ
- 無料枠のストレージを維持するため、一定期間後の投稿を自動削除・アーカイブするロジック。

## 6. 法的・運営要件（リリースのための「守り」）

### 必須ページ
- **利用規約・プライバシーポリシー**: サービスのルールを明文化したページの設置。
- **お問い合わせ窓口**: 要望や不具合を受け付ける連絡手段の確保。
