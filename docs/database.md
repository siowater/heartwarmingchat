# データベース設計

## 概要
本プロジェクトはFirebase Firestoreを使用します。NoSQLデータベースの特性を活かしたスキーマ設計を行います。

## コレクション一覧

### 1. users（ユーザー）
ユーザー情報を格納するコレクション。

| フィールド名 | 型 | 説明 | 必須 | インデックス |
|------------|-----|------|------|------------|
| userId | string | ユーザーID（Firebase Auth UID） | ✅ | プライマリキー |
| nickname | string | ニックネーム（最大50文字） | ❌ | - |
| authProvider | string | 認証プロバイダー（google/twitter/anonymous） | ✅ | - |
| status | string | ステータス（active/locked/suspended） | ✅ | - |
| createdAt | timestamp | アカウント作成日時 | ✅ | - |
| lastLoginAt | timestamp | 最終ログイン日時 | ✅ | - |

**セキュリティルール**: ユーザーは自分の情報のみ読み取り可能、更新は自分の情報のみ可能

---

### 2. posts（投稿）
投稿情報を格納するコレクション。

| フィールド名 | 型 | 説明 | 必須 | インデックス |
|------------|-----|------|------|------------|
| postId | string | 投稿ID | ✅ | プライマリキー |
| userId | string | 投稿者のユーザーID | ✅ | ✅ |
| content | string | 投稿内容（最大1000文字） | ✅ | - |
| createdAt | timestamp | 投稿作成日時 | ✅ | ✅（降順） |
| updatedAt | timestamp | 投稿更新日時 | ❌ | - |
| deletedAt | timestamp | 削除日時（論理削除） | ❌ | - |
| archivedAt | timestamp | アーカイブ日時 | ❌ | ✅ |
| reportCount | number | 通報数 | ✅ | - |
| isHidden | boolean | 非表示フラグ | ✅ | ✅ |
| filterResult | object | NGワードフィルタリング結果 | ❌ | - |

**セキュリティルール**: 全ユーザーが読み取り可能、作成は認証済みユーザーのみ、更新・削除は投稿者のみ

**インデックス**:
- `createdAt` 降順（新着順表示用）
- `userId` + `createdAt` 降順（ユーザー別投稿一覧用）
- `isHidden` + `createdAt` 降順（表示可能な投稿のみ取得用）

---

### 3. replies（返信）
返信情報を格納するコレクション。

| フィールド名 | 型 | 説明 | 必須 | インデックス |
|------------|-----|------|------|------------|
| replyId | string | 返信ID | ✅ | プライマリキー |
| postId | string | 返信先の投稿ID | ✅ | ✅ |
| userId | string | 返信者のユーザーID | ✅ | ✅ |
| content | string | 返信内容（最大500文字） | ✅ | - |
| createdAt | timestamp | 返信作成日時 | ✅ | ✅（昇順） |
| updatedAt | timestamp | 返信更新日時 | ❌ | - |
| deletedAt | timestamp | 削除日時（論理削除） | ❌ | - |
| reportCount | number | 通報数 | ✅ | - |
| isHidden | boolean | 非表示フラグ | ✅ | ✅ |
| filterResult | object | NGワードフィルタリング結果 | ❌ | - |

**セキュリティルール**: 全ユーザーが読み取り可能、作成は認証済みユーザーのみ、更新・削除は返信者のみ

**インデックス**:
- `postId` + `createdAt` 昇順（投稿別返信一覧用）
- `userId` + `createdAt` 降順（ユーザー別返信一覧用）
- `isHidden` + `createdAt` 昇順（表示可能な返信のみ取得用）

---

### 4. reactions（リアクション）
リアクション情報を格納するコレクション。

| フィールド名 | 型 | 説明 | 必須 | インデックス |
|------------|-----|------|------|------------|
| reactionId | string | リアクションID | ✅ | プライマリキー |
| targetType | string | 対象タイプ（post/reply） | ✅ | ✅ |
| targetId | string | 対象ID（投稿IDまたは返信ID） | ✅ | ✅ |
| userId | string | リアクションしたユーザーID | ✅ | ✅ |
| reactionType | string | リアクションタイプ（ありがとう/心が温まった/応援してる） | ✅ | - |
| createdAt | timestamp | リアクション作成日時 | ✅ | - |

**セキュリティルール**: 全ユーザーが読み取り可能、作成・削除は認証済みユーザーのみ（自分のみ削除可能）

**インデックス**:
- `targetType` + `targetId` + `userId`（1ユーザー1リアクション制約用、複合ユニーク）
- `targetType` + `targetId` + `createdAt`（対象別リアクション集計用）
- `userId` + `createdAt` 降順（ユーザー別リアクション履歴用）

---

| contributionScore | number | 貢献スコア（計算値） | ✅ | ✅（降順） |

**セキュリティルール**: 全ユーザーが読み取り可能、更新はシステムのみ（Cloud Functions等）

**インデックス**:
- `contributionScore` 降順（ランキング表示用）

## データリレーション

### 投稿と返信
- 1つの投稿に対して複数の返信が存在（1対多）
- 投稿が削除されると、関連する返信も非表示になる

### 投稿とリアクション
- 1つの投稿に対して複数のリアクションが存在（1対多）
- 1ユーザーは1投稿に対して1リアクションのみ

### 返信とリアクション
- 1つの返信に対して複数のリアクションが存在（1対多）
- 1ユーザーは1返信に対して1リアクションのみ

### ユーザーと投稿
- 1ユーザーは複数の投稿を作成可能（1対多）

### ユーザーと返信
- 1ユーザーは複数の返信を作成可能（1対多）

### ユーザーと貢献度
- 1ユーザーに対して1つの貢献度レコードが存在（1対1）

## データ保持ポリシー

### 自動アーカイブ
- 投稿: 作成後30日経過で自動アーカイブ
- アーカイブされた投稿は一覧表示から除外されるが、データは保持

### 自動削除
- 投稿: 作成後90日経過で自動削除
- 通知: 作成後30日経過で自動削除
- 削除されたデータは完全に削除され、復元不可

### 論理削除
- 投稿・返信は論理削除（deletedAtフィールドに日時を設定）
- 論理削除されたデータは表示されないが、データは保持

## セキュリティルール（概要）

### 基本方針
- 認証済みユーザーのみが作成・更新・削除可能
- 読み取りは基本的に全ユーザー可能（非表示フラグで制御）
- 自分のデータのみ更新・削除可能
- 管理者権限は将来実装（現時点ではFirebase Admin SDKで管理）

### 詳細なルール
各コレクションのセキュリティルールは、上記のCRUD表に基づいて実装します。
