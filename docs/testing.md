# テスト手順書

## 概要
本ドキュメントでは、優しさの交換サイトのテスト手順を説明します。

## テスト環境の準備

### 1. ローカル環境のセットアップ

```bash
# 依存関係のインストール
npm install

# 環境変数の設定
cp .env.local.example .env.local
# .env.localにFirebase設定を記入

# 開発サーバーの起動
npm run dev
```

### 2. Firebaseプロジェクトの設定

テスト用のFirebaseプロジェクトを作成することを推奨します。

## 機能テスト

### 認証機能

#### テストケース 1: Google認証
1. `/login` にアクセス
2. 「Googleでログイン」をクリック
3. Googleアカウントでログイン
4. ホームページにリダイレクトされることを確認
5. ナビゲーションバーに「マイページ」「設定」が表示されることを確認

#### テストケース 2: Twitter認証
1. `/login` にアクセス
2. 「Twitterでログイン」をクリック
3. Twitterアカウントでログイン
4. ホームページにリダイレクトされることを確認

#### テストケース 3: 匿名認証
1. `/login` にアクセス
2. 「匿名でログイン」をクリック
3. ホームページにリダイレクトされることを確認

#### テストケース 4: ログアウト
1. ログイン状態で「ログアウト」をクリック
2. `/login` にリダイレクトされることを確認

### 投稿機能

#### テストケース 5: 投稿作成（正常系）
1. ログイン状態で `/posts/new` にアクセス
2. 投稿内容を入力（1000文字以内）
3. 「投稿する」をクリック
4. トースト通知が表示されることを確認
5. ホームページにリダイレクトされることを確認
6. 投稿一覧に新しい投稿が表示されることを確認

#### テストケース 6: 投稿作成（バリデーション）
1. ログイン状態で `/posts/new` にアクセス
2. 空の状態で「投稿する」をクリック
3. エラーメッセージが表示されることを確認
4. 1000文字を超える内容を入力
5. エラーメッセージが表示されることを確認

#### テストケース 7: NGワードフィルタリング
1. ログイン状態で `/posts/new` にアクセス
2. NGワードを含む内容を入力
3. 「投稿する」をクリック
4. エラーメッセージが表示されることを確認
5. 投稿が作成されないことを確認

#### テストケース 8: 投稿数制限
1. ログイン状態で10件の投稿を作成
2. 11件目の投稿を作成しようとする
3. エラーメッセージが表示されることを確認

### 返信機能

#### テストケース 9: 返信作成（正常系）
1. 投稿詳細ページにアクセス
2. 返信フォームに内容を入力（500文字以内）
3. 「返信する」をクリック
4. トースト通知が表示されることを確認
5. 返信一覧に新しい返信が表示されることを確認

#### テストケース 10: 返信作成（バリデーション）
1. 投稿詳細ページにアクセス
2. 空の状態で「返信する」をクリック
3. エラーメッセージが表示されることを確認
4. 500文字を超える内容を入力
5. エラーメッセージが表示されることを確認

#### テストケース 11: 自分の投稿への返信不可
1. 自分の投稿の詳細ページにアクセス
2. 返信フォームが表示されない、またはエラーが表示されることを確認

#### テストケース 12: 1投稿1ユーザー1件の制限
1. 投稿に返信を作成
2. 同じ投稿に再度返信を作成しようとする
3. エラーメッセージが表示されることを確認

### リアクション機能

#### テストケース 13: リアクション送信
1. 投稿詳細ページにアクセス
2. 「ありがとう」ボタンをクリック
3. トースト通知が表示されることを確認
4. リアクション数が増加することを確認
5. ボタンがアクティブ状態になることを確認

#### テストケース 14: リアクション取消
1. リアクション済みの投稿でリアクションボタンをクリック
2. リアクションが取り消されることを確認
3. リアクション数が減少することを確認

#### テストケース 15: 自分の投稿へのリアクション不可
1. 自分の投稿の詳細ページにアクセス
2. リアクションボタンが無効化されている、またはエラーが表示されることを確認

### 通知機能

#### テストケース 16: リアクション通知
1. ユーザーAで投稿を作成
2. ユーザーBでログイン
3. ユーザーAの投稿にリアクションを送信
4. ユーザーAでログイン
5. 通知バッジに未読数が表示されることを確認
6. `/notifications` にアクセス
7. リアクション通知が表示されることを確認

#### テストケース 17: 返信通知
1. ユーザーAで投稿を作成
2. ユーザーBでログイン
3. ユーザーAの投稿に返信を作成
4. ユーザーAでログイン
5. 通知バッジに未読数が表示されることを確認
6. `/notifications` にアクセス
7. 返信通知が表示されることを確認

#### テストケース 18: 通知既読処理
1. `/notifications` にアクセス
2. 未読通知をクリック
3. 通知が既読状態になることを確認
4. 「すべて既読にする」をクリック
5. すべての通知が既読状態になることを確認

### ランキング機能

#### テストケース 19: ランキング表示
1. `/ranking` にアクセス
2. ランキング一覧が表示されることを確認

### マイページ機能

#### テストケース 20: マイページ表示
1. ログイン状態で `/profile` にアクセス
2. ユーザー情報が表示されることを確認
3. 貢献度が表示されることを確認
4. 投稿履歴が表示されることを確認
5. 返信履歴が表示されることを確認

### 通報機能

#### テストケース 21: 通報送信
1. 投稿詳細ページにアクセス
2. 「通報する」をクリック
3. 通報理由を選択
4. 「通報する」をクリック
5. 成功メッセージが表示されることを確認

#### テストケース 22: 通報数による自動非表示
1. 投稿に対して5件の通報を送信
2. 投稿が自動的に非表示になることを確認

### ソート機能

#### テストケース 23: 投稿ソート
1. ホームページにアクセス
2. 「新着順」を選択
3. 投稿が新着順で表示されることを確認
4. 「ランダム」を選択
5. 投稿がランダムに表示されることを確認
6. 「リアクション順」を選択
7. 投稿がリアクション数順で表示されることを確認

## レスポンシブテスト

### モバイル表示

#### テストケース 24: モバイル表示

2. すべてのページが正常に表示されることを確認
3. ナビゲーションバーが適切に表示されることを確認
4. フォームが使いやすいことを確認

### タブレット表示

#### テストケース 25: タブレット表示
1. ブラウザの開発者ツールでタブレット表示に切り替え（768px幅）

## パフォーマンステスト

### テストケース 26: ページ読み込み速度
1. Chrome DevToolsのLighthouseを使用
2. Performanceスコアが80以上であることを確認
3. First Contentful Paintが2秒以内であることを確認

### テストケース 27: 無限スクロール
1. ホームページで投稿一覧をスクロール
2. 「もっと見る」ボタンをクリック
3. 追加の投稿が読み込まれることを確認

## セキュリティテスト

### テストケース 28: 認証チェック
1. ログアウト状態で `/posts/new` にアクセス
2. `/login` にリダイレクトされることを確認

### テストケース 29: セキュリティルール
1. Firestoreのセキュリティルールが正しく設定されていることを確認
2. 他のユーザーのデータにアクセスできないことを確認

### テストケース 30: ネットワークエラー

2. 投稿を作成しようとする
3. 適切なエラーメッセージが表示されることを確認

### テストケース 31: Firebase接続エラー

2. アプリケーションを起動

## テスト結果の記録

各テストケースの結果を記録：

- ✅ 合格
- ❌ 不合格（問題点を記録）
- ⏸️ スキップ（理由を記録）

## 継続的テスト

### 開発時のテスト

- 新機能追加時は必ずテストを実行
- バグ修正時は関連するテストケースを再実行

### デプロイ前のテスト

- すべてのテストケースを実行
- 問題がないことを確認してからデプロイ
